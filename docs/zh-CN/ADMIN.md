# 管理面板

**语言：** [English](../en/ADMIN.md) | 简体中文 | [繁體中文](../zh-TW/ADMIN.md) | [日本語](../ja/ADMIN.md) | [한국어](../ko/ADMIN.md)

管理面板是**可选的**：没设 `ADMIN_TOKEN` 时整棵 `/admin` 树根本不注册，而网关照常转发。
本文讲的是面板上看得见的那一半——每个板块回答什么问题、屏幕上那些数字是什么口径、
哪些动作会写盘。**变量本身（默认值、取值范围、代价）全仓只有一份，在
[DEPLOY.md](DEPLOY.md) 的环境变量表里**，本文一律只给指路，不抄第二份。

本文覆盖：怎么进面板，八个板块逐个过一遍，最后是面板不做什么与排障。

## 怎么进面板

- **地址**：`https://<your-gateway>/admin`，把 `<your-gateway>` 换成你自己的网关地址。
  带尾斜杠的 `/admin/` 会自动跳到 `/admin`，两种手输写法都进得去。
- **前置条件只有一条**：部署时设好 `ADMIN_TOKEN`。它必须至少 24 位、只由可打印 ASCII
  组成、并且与 `GATEWAY_TOKEN` 不同。这三条各自的理由、边界，以及不合规时会记下哪条
  事件，都在 [DEPLOY.md](DEPLOY.md) 的「管理面板相关变量」一节。
- **没设或不合规时，`/admin` 给的是 `404` 而不是 `401`**：整棵树压根没注册，所以它
  不会顺带告诉外面「这里有个后台」。面板打不开也**不影响网关转发**。
- **口令原样存在浏览器的 localStorage 里**，面板会在 12 小时后要求你重新输入。
- 那个上限只缩短这份 localStorage 值的可用窗口，**不等于撤销**：撤销的唯一路径是换掉
  `ADMIN_TOKEN` 再重新部署 / 重建容器。请把面板放在 TLS 之后，并且只在你信任的机器上
  打开它——完整论证见 [DEPLOY.md](DEPLOY.md) 的「管理口令泄漏」那一段。

## 八个板块速查

| 板块 | 它回答什么问题 | 只读还是会写 | 依赖哪个开关 |
|---|---|---|---|
| 概览 | 这个部署现在是什么形态，池子还剩多少可用 key | 只读 | – |
| Key 池 | 每一把 key 现在是什么状态，为什么不可用 | 会写 | – |
| 注册机 | 自动补池在不在跑，上几轮补了什么 | 会写 | `REGISTRAR_ENABLED` |
| 事件 | 最近发生过哪些运维级别的事 | 只读 | – |
| 用量 | 请求量、成功率、延迟随时间怎么变 | 只读 | `USAGE_STATS_ENABLED`（只管第二层） |
| 模型 | 网关对外承认哪些模型，各自支持什么模态与协议 | 只读 | – |
| 调试台 | 用一次真的请求验一遍某条协议通不通 | 打上游 | – |
| 设置 | 运行时配置现在是什么值，哪几项被环境变量锁住了 | 会写 | – |

「会写」指的是**你在这一页上按下的动作会写存储**；「打上游」指的是真的向上游发一次请求。
⚠️ **「打上游」不等于「不写存储」**：调试台发的是一次打到本网关自己转发口的真请求，它和
任何一次转发走的是同一条路——这次用掉的那把 key 照样要记账，落盘口径与转发路径完全一样
（同样是攒批的），第二层用量开着时还会多记一笔。

## 概览

概览回答一个问题：**这个部署现在是什么形态、池子还剩多少可用 key。**

- **池子五个桶**：总数 / 可用 / 冷却中 / 已剔除 / 已停用。五格恒显示，一个真实的 `0`
  本来就是真话；**读不出来时那一格显示 `—`，绝不伪造 `0`**——这两件事在屏幕上必须
  长得不一样。
- **运行时与存储自述**：运行时名字、版本、服务端时间、存储后端、可写与否，以及
  Node 形态才有的内存 / 存活时长 / PID。这些一律取自接口返回的数据，面板不去嗅探
  自己跑在哪种运行时上；Worker 形态没有常驻进程，那三格写的是「无常驻进程」，
  不是 `0`、也不是空白。
- **两条新鲜度**：池快照与配置各有各的「几秒前读到的」。它们不是同一条时间线，所以
  分开显示。池快照那条的迟滞由 `POOL_CACHE_TTL_MS` 决定，还要再叠一层边缘缓存，
  上界与代价在 [DEPLOY.md](DEPLOY.md) 的那一格里写着。
- **第一层累计用量**：请求数 / 成功 / 失败 / 客户端错误 / 成功率。它是整池所有 key 的
  累计聚合，因此标着 `≈`：单把 key 的计数在并发下会少计（KV 没有 CAS），而且最多晚
  一个 `POOL_TOUCH_INTERVAL_MS` 才落盘。
- **配置摘要**：注册机开关、主备通道、`TARGET_KEYS` 这几项的当前生效值。被环境变量
  锁住的字段带一个锁定标记——那几项在设置页改了也不会生效，因为环境变量的优先级更高。

## Key 池

- **桶徽章是一次优先级投影**，不是四个独立标志：一把 key 同时满足多个条件时，按
  已停用 > 已剔除 > 冷却中 > 可用 取第一个。所以一把「被停用、同时还在冷却」的 key，
  徽章上写的是「已停用」——它的冷却并没有消失，只是徽章上看不见。
- **八个单条动作**：停用、启用、清冷却、清失败计数、取消剔除、改备注、验活、删除。
- **三个批量动作**：批量停用、批量清冷却、批量删除。
- **一次最多导入 200 把 key**。超过这个数直接 `400`，**不静默截断**——截断意味着你以为
  导进去了而其实没有。
- **「重置已存在 key 的状态」这个勾选框到底重置什么**：它重置的是**系统判定的失败态**
  ——失败计数、冷却截止时刻、冷却原因、剔除标记、剔除原因。它**刻意不动**另外四样：
  停用状态（那是你自己按下的开关，一次粘贴不该把它静默翻回去）、加入时间（来历不是
  失败态）、用量统计（历史不是失败态）、备注（你写给自己看的话）。
- **要删掉一把 key，它必须已停用或已被系统剔除**：两者满足其一即可——已被剔除的那些
  不必再手动停用一次。直接删一把仍在服役的 key 会被拒绝；这条约束在批量路径上不是整批
  失败，而是逐项给出原因。
- **单把验活**会拿这把 key 真的打一次上游。列表里的「最后使用」与用量计数是攒着落盘的，
  精度最粗到 `POOL_TOUCH_INTERVAL_MS` 这个间隔。

## 注册机

面板上的注册机板块是**索引，不是说明书**：补池的全部规则、通道怎么选、要自备哪些凭据、
出事怎么排查，全在 [REGISTRAR.md](REGISTRAR.md) 里，本文不抄第二份。板块上看得到的是：

- **两条邮箱通道是平级的**，没有默认值：主通道必须显式指定，备通道可以不配。板块显示
  它们各自的角色（主 / 备）与凭据配没配。
- **补池历史**：每一轮什么时候跑的、走的哪条通道、由定时器还是由人触发、跑了多久。
- **通道测试只读取这条通道的可用域名列表**，不建邮箱、不注册账号、不消耗任何名额。
- **「立即补池」有四条护栏**，任何一条不满足都不会启动：同副本的在途守卫、跨副本的
  存储短锁、两次手动补池之间的最小间隔、每天的手动次数上限。四条各自的错误码、算式
  与残余风险在 [REGISTRAR.md](REGISTRAR.md) 的「面板的「立即补池」」一节。
- 注册机没打开（`REGISTRAR_ENABLED` 不为 `true`）时板块照样看得见，只是状态显示为关闭，
  「立即补池」会被后端拒绝。

## 事件

- 这里只有**低频结构化事件**：配置读取失败、池索引重建、管理接口登录失败这类运维诊断，
  加上注册机的补池事件与面板自己的写操作。**key 被转发路径自动打进冷却或剔除时目前
  不产出事件**——那一段要回 Key 池板块看那把 key 自己的状态。
- **工具条**：按级别筛选、按文本搜索、暂停自动刷新、清空、下载。「清空」只清屏幕上
  这一份列表，**不动服务端已经落盘的事件**；要重看请点「下载」或刷新页面。
- **事件按小时分窗口存放，一共留 24 个窗口**——也就是整整一天，更早的会自然过期，
  面板上再也查不到。
- 警告条各自在说一件不同的事，**它们是彼此独立的几条，可能同时亮起**：

| 警告条 | 它在说什么 | 你该做什么 |
|---|---|---|
| 丢弃 | 本副本的事件缓冲把最旧的几条挤掉了，它们没来得及落盘 | 事件产生得比落盘快；去容器日志 / Workers Logs 里找那一段 |
| 预算 | 本副本今天的事件写入预算已经用完 | 同上：没落盘的那些仍然在日志里 |
| 截断 | 这一页没显示全部符合条件的事件 | 收窄筛选条件，或者缩短要看的时间范围 |
| 游标领先 | 拉取位置领先于服务端时钟：时钟回拨，或者副本之间有时钟偏移 | 面板已经自动从新位置重拉，这一条会自愈 |
| 游标不合契约 | 接口返回的游标既不是数字也不是空，面板保留了上一个游标——**再往后可能一直看不到新事件** | 查事件存储是不是被本网关之外的东西写过 |

## 用量

- **用量分两层，第一层永远在**。第一层是整池累计的那几个数（概览页顶上那张卡用的就是
  它），不需要任何开关。第二层是按天 / 小时 / 模型 / 协议分解的时间序列，由
  `USAGE_STATS_ENABLED` 控制，**默认是关的**。
- **关着的时候这一页不画空图表**：一张全是 `0` 的图会被读成「这段时间没人用」，而真相
  是「这个部署根本没在记账」。这两件事不许长得一样。
- **四档时间范围**：`24h`、`3d`、`7d`、`30d`。
- **最多保留 30 天**，更早的数据已经过期。最长那一档一次要把整段区间的分片全部读回来，
  它在 Cloudflare Worker 上是否总能跑完，本仓尚未在真机上量过——失败时这一页如实显示
  为读取失败，不会给出一份看起来完整的数字。
- **这里的数字标着 `≈`，三个来源各不相同**：① 未落盘的尾巴——计数先攒在实例内存里，
  隔一阵才批量写盘，这段窗口有多长面板自己会告诉你；② 短命实例——那一段还没写盘就被
  回收的话就没了；③ 同一天里的分片只有 2 个槽位，同时写的副本比这更多时，同槽位是
  后写覆盖前写。
- **读不出来时显示 `—`，不是 `0`**：「今天真的是 0 次请求」「第二层没开」「这一次读失败了」
  是三件事，面板不许把它们画成同一个样子。

## 模型

- **这一页回答一个问题**：这个网关对外承认哪些模型、每个模型是什么类型、在哪几条协议上
  真的可用、以及该打哪条端点。
- **三种类型**：对话、图片、视频。对话模型挂在四条对话协议上；图片与视频模型的协议那一列
  是空的——它们不属于任何一条对话协议，走的是各自的媒体端点。
- **协议可用性是一格一格的徽章**，不是一句「支持」或「不支持」：同一个模型在一条协议上
  可用、在另一条上不可用是常态。可以按协议筛选；筛出来一个都没有时，这一页直接说
  「这条协议上没有可用的模型」，不画一张空表。
- **端点那一列给的是「客户端该打哪条路径」**，与 [API.md](API.md) 出自同一份真源，
  本文不抄第二份。
- **目录读不出来时这一页显示一根破折号**，并且明说这不等于「这个网关一个模型都没有」
  ——这两件事在屏幕上必须分得开。
- ⚠️ **有一处已知的对外分歧，如实登记**：Gemini 那条协议的模型列表接口对**全部**模型
  一律声明支持 `generateContent`，**包括那个视频模型**；而视频真正的路径是「建任务 +
  轮询」两段式。面板这一页按真实可用性填，两边对不上时以这一页为准。

## 调试台

- **两把钥匙严格隔离，这是这一页最要紧的一件事。** 面板口令走 `x-admin-key`，只打
  `/admin/api` 那棵树；调试台用的是**网关口令**（`GATEWAY_TOKEN`），走各条协议惯用的
  鉴权头打对外那棵树。两把钥匙分开存在浏览器里，**退出登录时一起清掉**——共享或
  投屏的机器上，不清的那一把会原样留给下一个人。
- **网关口令要你手动粘一次，没有「一键填入」**：面板读不到它的明文（凭据只写不读），
  只能把设置页里存着的末 4 位与你粘的这一把比一比，然后告诉你「一致」「对不上」
  还是「读不到，这次比不了」。
- **三种模式，各自能配的东西不一样**：

| 模式 | 打的是哪条端点 | 这一档能配什么 |
|---|---|---|
| 对话 | 四条对话协议各自的对外路径 | 挑协议、挑模型，可以开流式 |
| 图片 | 图片生成那一条端点 | 只挑模型；没有协议选择器，也没有流式开关 |
| 视频 | 建任务与查结果两条端点 | 只挑模型；建完任务自动轮询结果 |

**协议选择器与流式开关只在对话档出现**，不是被藏起来了：媒体那两条端点在协议目录里
不属于任何一条对话协议，摆一排点不动的按钮只会让人以为图片也能挑协议、也能流式。

- **流式这一档不显示 token 数**：面板在流式下不读用量，写一个 `0` 会是假的，所以那一格
  干脆不给数字。
- **视频是两段式的**：先建任务拿到任务标识，再拿这个标识轮询结果。轮询**每 5 秒一次，
  上限是 60 次 / 5 分钟**，先到哪条算哪条——今天这两条恰好等价（60 次 × 5 秒正好是
  5 分钟）；页面被藏起来过的话打点会暂停而墙钟照走，那时先到的是时长那一条。
- ⚠️ **真实上游生成一条视频要多久，本仓从来没有量过。** 这两条上限是拿来封住
  「一个忘了关的标签页变成一台永动打点机」的，不是从真实生成时长推出来的，本文
  也不对它们与真实生成时长的关系下任何结论。到上限时面板会明说「轮询已经到上限，
  先停下了」并把任务标识摆在那里——任务本身可能还在跑，你可以稍后自己拿这个标识再查。
- **建任务的响应里没有能用的任务标识时，面板不替你猜**：它只把固定的那几格当标识读，
  都读不到就不轮询，并把响应原文原样摆出来。
- **每一次按「发送」都是真的打上游**：那一次请求与任何一次转发走同一条路，用掉的那把
  key 照样记账（见速查表下面那句）。视频档一次是 1 次建任务，加上最多 60 次轮询查询。
- **屏幕上最多保留 20 轮对话**，更旧的会从这一页移除，面板会告诉你移除了几轮；也可以
  按「清空对话」自己清掉。清的只是屏幕上这一份，服务端什么都不动。

## 设置

设置页今天有四张卡：

| 卡 | 它管什么 | 要注意的 |
|---|---|---|
| 认证密钥 | 网关口令，以及各条邮箱通道自己的凭据 | 凭据只写不读：输入框留空 = 这一格不改 |
| 上游与冷却 | 上游地址、超时，以及冷却与剔除的那几个旋钮 | 其中两格是建实例时读一次的，见本节末尾 |
| 注册机 | 补池的全部旋钮，外加一个「高级」折叠区 | 折叠区里那一格改的是每一次自动注册的去向 |
| 集成示例 | 照抄就能跑的调用示例 | 地址取自你现在打开面板用的那个域名，口令是占位符 |

- **每一格都摊开一个四元组**：存储里是什么、环境变量里是什么、现在生效的是哪一个、
  以及是谁把它锁住的。优先级是**环境变量 > 存储里的值 > 内置默认**；被环境变量锁住的
  格子在这一页改了不会生效，面板会直接告诉你该去改部署那一侧的哪个变量。
- **凭据只写不读**：面板拿不到明文，屏幕上只有「已配置 / 未配置」与末 4 位。留空 = 不改；
  真要删掉得按「清空」，而那一步会先告诉你清完会发生什么——回落到环境变量里的值、
  下一次重启起不来、还是现在不影响任何东西。
- **保存之后面板不说「已保存并生效」**。它做的是三件事：回读一遍生效值、把真的变了的
  那几格高亮出来、再给出「别的副本 / isolate 最长多久才看得到这次改动」的上界。这个
  上界由配置缓存与 KV 边缘缓存两层相加得到，两个数都在 [DEPLOY.md](DEPLOY.md) 的
  环境变量表里。
- ⚠️ **有两个例外字段**：池快照缓存与写消除间隔（`POOL_CACHE_TTL_MS` 与
  `POOL_TOUCH_INTERVAL_MS`）是**建实例时读一次**的 ⇒ 保存之后**连本实例都还没生效**，
  要重启容器或者等 isolate 被回收。面板对这两格单说一句话，不会跟着说「本实例已经生效」。
- **面板改不了自己的钥匙**：`ADMIN_TOKEN` 只从环境变量读。要轮换它，改部署那一侧的
  环境变量再重启。
- **存储里那份配置装载不起来时这一页变成诊断视图**：逐条列出缺的是什么，而且**表单仍然
  可以编辑**——那是唯一的出路。

本文在它真的上线之前不写它会做什么：描述一个还不存在的功能，比什么都不写更坏。
上面那张表的行数是从面板自己的卡数派生出来的，所以危险区一落地，这份文档就会被测试
逼着回来改。

## 面板不做什么

- **不轮换自己的钥匙**：`ADMIN_TOKEN` 只从环境变量读，面板既改不了它，也没有
  「让已经发出去的会话立刻作废」这种撤销路径。换钥匙 = 改部署那一侧的变量，
  再重新部署或重建容器。
- **不回显任何凭据的明文**：后端对凭据只回「配没配」加末 4 位，所以面板做不出
  「把我的口令填进来」这种按钮——那需要在后端开一个明文回显的口子，而那个口子一开，
  「凭据只写不读」整条就没了。
- **不代替 `wrangler secret` 与 `.env`**：这一页改的是存储里那一份配置，而环境变量的
  优先级更高。两边不一致时屏幕上会有锁定标记，但把环境变量本身改掉这件事只能在
  部署那一侧做。
- **不替你把远端媒体拉下来**：调试台里的结果地址是原样列出来的，可以复制、可以在新
  标签页打开；只有 `data:` 形式的图片才会内嵌显示，那一档不向任何第三方发请求。

## 排障

- **打不开，而且是 `404`**：这个部署没设 `ADMIN_TOKEN`，或者设了但不合规。整棵树
  没注册，所以外面也看不出这里有没有后台。
- **打不开，而且是 `401`**：口令本身不对，多半是它已经被轮换过了。⚠️ **别把这一档与
  「面板把你退回登录框」混为一谈**：12 小时那条窗口是面板自己判的，到点时它一个请求都
  不会发出去，服务端那边什么记录都不会有。两种都只要重新输入一次。
- **打不开，而且是 `503`**：`ADMIN_TOKEN` 与存储里的网关口令撞成了同一个值。这条规则
  在每一个管理请求上复查，事件板块与日志里会有一条 `admin.token_conflict`。
  ⚠️ **把存储里的网关口令改回去只恢复可用性**：那把管理口令必须按已泄漏处置，
  完整步骤在 [DEPLOY.md](DEPLOY.md) 里，两步都做完才算处置完。
- **登录看起来成功了，却永远进不去**：口令里有浏览器根本发不出去的字符（码点超过
  `U+00FF` 的汉字、emoji、零宽空格，以及 NUL / LF / CR）。这种请求**压根没发出来**，
  所以服务端连一条登录失败都没有——这正是「口令只用可打印 ASCII」那条约束的理由。
- **屏幕上是旧值**：配置与池快照各有各的缓存窗口，外面还叠着一层 KV 边缘缓存。两条的
  上界与代价都在 [DEPLOY.md](DEPLOY.md) 的环境变量表里，本文不抄第二份；概览页那两条
  「几秒前读到的」就是给这件事看的。
- **报错是后端原话，不是你的语言**：面板对**它认得的**错误码显示本语言文案；碰上它
  不认得的码，就把后端那句原话摆出来，并在旁边标一句「这句是后端原话，本面板还没有
  这条错误码的译文」。⚠️ **别读成「所有错误都会用你的语言显示」**——认不出来的那些
  不会，而面板宁可把这件事标出来，也不冒充成一句译文。
