# 管理面板

**語言：** [English](../en/ADMIN.md) | [简体中文](../zh-CN/ADMIN.md) | 繁體中文 | [日本語](../ja/ADMIN.md) | [한국어](../ko/ADMIN.md)

管理面板是**可選的**：沒設 `ADMIN_TOKEN` 時整棵 `/admin` 樹根本不註冊，而閘道照常轉發。
本文講的是面板上看得見的那一半——每個板塊回答什麼問題、螢幕上那些數字是什麼口徑、
哪些動作會寫入儲存。**變數本身（預設值、取值範圍、代價）全倉只有一份，在
[DEPLOY.md](DEPLOY.md) 的環境變數表裡**，本文一律只給指路，不抄第二份。

本文涵蓋：怎麼進面板，每個板塊逐個過一遍，最後是面板不做什麼與排障。

## 怎麼進面板

- **位址**：`https://<your-gateway>/admin`，把 `<your-gateway>` 換成你自己的閘道位址。
  帶尾斜線的 `/admin/` 會自動跳到 `/admin`，兩種手動輸入的寫法都進得去。
- **前置條件只有一條**：部署時設好 `ADMIN_TOKEN`。它必須至少 24 位、只由可列印 ASCII
  組成、並且與 `GATEWAY_TOKEN` 不同。這三條各自的理由、邊界，以及不合規時會記下哪條
  事件，都在 [DEPLOY.md](DEPLOY.md) 的「管理面板相關變數」一節。
- **沒設或不合規時，`/admin` 給的是 `404` 而不是 `401`**：整棵樹壓根沒註冊，所以它
  不會順帶告訴外面「這裡有個後台」。面板打不開也**不影響閘道轉發**。
- **口令原樣存在瀏覽器的 localStorage 裡**，面板會在 12 小時後要求你重新輸入。
- 那個上限只縮短這份 localStorage 值的可用視窗，**不等於撤銷**：撤銷的唯一路徑是換掉
  `ADMIN_TOKEN` 再重新部署 / 重建容器。請把面板放在 TLS 之後，並且只在你信任的機器上
  打開它——完整論證見 [DEPLOY.md](DEPLOY.md) 的「管理口令外洩」那一段。

## 八個板塊速查

| 板塊 | 它回答什麼問題 | 唯讀還是會寫 | 依賴哪個開關 |
|---|---|---|---|
| 概覽 | 這個部署現在是什麼形態，池子還剩多少可用 key | 唯讀 | – |
| Key 池 | 每一把 key 現在是什麼狀態，為什麼不可用 | 會寫 | – |
| 註冊機 | 自動補池在不在跑，上幾輪補了什麼 | 會寫 | `REGISTRAR_ENABLED` |
| 事件 | 最近發生過哪些維運級別的事 | 唯讀 | – |
| 用量 | 請求量、成功率、延遲隨時間怎麼變 | 唯讀 | `USAGE_STATS_ENABLED`（只管第二層） |
| 模型 | 閘道對外承認哪些模型，各自支援什麼模態與協定 | 唯讀 | – |
| 除錯台 | 用一次真的請求驗一遍某條協定通不通 | 打上游 | – |
| 設定 | 執行期設定現在是什麼值，哪幾項被環境變數鎖住了 | 會寫 | – |

「會寫」指的是**你在這一頁上按下的動作會寫儲存**；「打上游」指的是真的向上游發一次請求。
⚠️ **「打上游」不等於「不寫儲存」**：除錯台發的是一次打到本閘道自己轉發口的真請求，它和
任何一次轉發走的是同一條路——這次用掉的那把 key 照樣要記帳，寫入口徑與轉發路徑完全一樣
（同樣是攢批的），第二層用量開著時還會多記一筆。

## 概覽

概覽回答一個問題：**這個部署現在是什麼形態、池子還剩多少可用 key。**

- **池子五個桶**：總數 / 可用 / 冷卻中 / 已剔除 / 已停用。五格恆顯示，一個真實的 `0`
  本來就是真話；**讀不出來時那一格顯示 `—`，絕不偽造 `0`**——這兩件事在螢幕上必須
  長得不一樣。
- **執行期與儲存自述**：執行期名字、版本、伺服端時間、儲存後端、可寫與否，以及
  Node 形態才有的記憶體 / 存活時長 / PID。這些一律取自介面回傳的資料，面板不去嗅探
  自己跑在哪種執行期上；Worker 形態沒有常駐行程，那三格寫的是「無常駐行程」，
  不是 `0`、也不是空白。
- **兩條新鮮度**：池快照與設定各有各的「幾秒前讀到的」。它們不是同一條時間線，所以
  分開顯示。池快照那條的遲滯由 `POOL_CACHE_TTL_MS` 決定，還要再疊一層邊緣快取，
  上界與代價在 [DEPLOY.md](DEPLOY.md) 的那一格裡寫著。
- **第一層累計用量**：請求數 / 成功 / 失敗 / 客戶端錯誤 / 成功率。它是整池所有 key 的
  累計聚合，因此標著 `≈`：單把 key 的計數在並行下會少計（KV 沒有 CAS），而且最多晚
  一個 `POOL_TOUCH_INTERVAL_MS` 才寫入。
- **設定摘要**：註冊機開關、主備通道、`TARGET_KEYS` 這幾項的目前生效值。被環境變數
  鎖住的欄位帶一個鎖定標記——那幾項在設定頁改了也不會生效，因為環境變數的優先權更高。

## Key 池

- **桶徽章是一次優先權投影**，不是四個獨立標誌：一把 key 同時滿足多個條件時，按
  已停用 > 已剔除 > 冷卻中 > 可用 取第一個。所以一把「被停用、同時還在冷卻」的 key，
  徽章上寫的是「已停用」——它的冷卻並沒有消失，只是徽章上看不見。
- **八個單條動作**：停用、啟用、清冷卻、清失敗計數、取消剔除、改備註、驗活、刪除。
- **三個批次動作**：批次停用、批次清冷卻、批次刪除。
- **一次最多匯入 200 把 key**。超過這個數直接 `400`，**不靜默截斷**——截斷意味著你以為
  匯進去了而其實沒有。
- **「重設已存在 key 的狀態」這個勾選框到底重設什麼**：它重設的是**系統判定的失敗態**
  ——失敗計數、冷卻截止時刻、冷卻原因、剔除標記、剔除原因。它**刻意不動**另外四樣：
  停用狀態（那是你自己按下的開關，一次貼上不該把它靜默翻回去）、加入時間（來歷不是
  失敗態）、用量統計（歷史不是失敗態）、備註（你寫給自己看的話）。
- **要刪掉一把 key，它必須已停用或已被系統剔除**：兩者滿足其一即可——已被剔除的那些
  不必再手動停用一次。直接刪一把仍在服役的 key 會被拒絕；這條約束在批次路徑上不是整批
  失敗，而是逐項給出原因。
- **單把驗活**會拿這把 key 真的打一次上游。清單裡的「最後使用」與用量計數是攢著寫入的，
  精度最粗到 `POOL_TOUCH_INTERVAL_MS` 這個間隔。

## 註冊機

面板上的註冊機板塊是**索引，不是說明書**：補池的全部規則、通道怎麼選、要自備哪些憑證、
出事怎麼排查，全在 [REGISTRAR.md](REGISTRAR.md) 裡，本文不抄第二份。板塊上看得到的是：

- **兩條郵箱通道是平級的**，沒有預設值：主通道必須明確指定，備通道可以不配。板塊顯示
  它們各自的角色（主 / 備）與憑證配沒配。
- **補池歷史**：每一輪什麼時候跑的、走的哪條通道、由定時器還是由人觸發、跑了多久。
- **通道測試只讀取這條通道的可用網域清單**，不建郵箱、不註冊帳號、不消耗任何名額。
- **「立即補池」有四條護欄**，任何一條不滿足都不會啟動：同副本的在途守衛、跨副本的
  儲存短鎖、兩次手動補池之間的最小間隔、每天的手動次數上限。四條各自的錯誤碼、算式
  與殘餘風險在 [REGISTRAR.md](REGISTRAR.md) 的「面板的「立即補池」」一節。
- 註冊機沒打開（`REGISTRAR_ENABLED` 不為 `true`）時板塊照樣看得見，只是狀態顯示為關閉，
  「立即補池」會被後端拒絕。

## 事件

- 這裡只有**低頻結構化事件**：設定讀取失敗、池索引重建、管理介面登入失敗這類維運診斷，
  加上註冊機的補池事件與面板自己的寫操作。**key 被轉發路徑自動打進冷卻或剔除時目前
  不產出事件**——那一段要回 Key 池板塊看那把 key 自己的狀態。
- **工具列**：按級別篩選、按文字搜尋、暫停自動重新整理、清空、下載。「清空」只清螢幕上
  這一份清單，**不動伺服端已經寫入的事件**；要重看請點「下載」或重新整理頁面。
- **事件按小時分視窗存放，一共留 24 個視窗**——也就是整整一天，更早的會自然過期，
  面板上再也查不到。
- 警告條各自在說一件不同的事，**它們是彼此獨立的幾條，可能同時亮起**：

| 警告條 | 它在說什麼 | 你該做什麼 |
|---|---|---|
| 丟棄 | 本副本的事件緩衝把最舊的幾條擠掉了，它們沒來得及寫入 | 事件產生得比寫入快；去容器日誌 / Workers Logs 裡找那一段 |
| 預算 | 本副本今天的事件寫入預算已經用完 | 同上：沒寫入的那些仍然在日誌裡 |
| 截斷 | 這一頁沒顯示全部符合條件的事件 | 收窄篩選條件，或者縮短要看的時間範圍 |
| 游標領先 | 擷取位置領先於伺服端時鐘：時鐘回撥，或者副本之間有時鐘偏移 | 面板已經自動從新位置重拉，這一條會自癒 |
| 游標不合契約 | 介面回傳的游標既不是數字也不是空，面板保留了上一個游標——**再往後可能一直看不到新事件** | 查事件儲存是不是被本閘道之外的東西寫過 |

## 用量

- **用量分兩層，第一層永遠在**。第一層是整池累計的那幾個數（概覽頁頂上那張卡用的就是
  它），不需要任何開關。第二層是按天 / 小時 / 模型 / 協定分解的時間序列，由
  `USAGE_STATS_ENABLED` 控制，**預設是關的**。
- **關著的時候這一頁不畫空圖表**：一張全是 `0` 的圖會被讀成「這段時間沒人用」，而真相
  是「這個部署根本沒在記帳」。這兩件事不許長得一樣。
- **四檔時間範圍**：`24h`、`3d`、`7d`、`30d`。
- **最多保留 30 天**，更早的資料已經過期。最長那一檔一次要把整段區間的分片全部讀回來，
  它在 Cloudflare Worker 上是否總能跑完，本倉尚未在真機上量過——失敗時這一頁如實顯示
  為讀取失敗，不會給出一份看起來完整的數字。
- **這裡的數字標著 `≈`，三個來源各不相同**：① 未寫入的尾巴——計數先攢在實例記憶體裡，
  隔一陣才批次寫入，這段視窗有多長面板自己會告訴你；② 短命實例——那一段還沒寫入就被
  回收的話就沒了；③ 同一天裡的分片只有 2 個槽位，同時寫的副本比這更多時，同槽位是
  後寫覆蓋前寫。
- **讀不出來時顯示 `—`，不是 `0`**：「今天真的是 0 次請求」「第二層沒開」「這一次讀失敗了」
  是三件事，面板不許把它們畫成同一個樣子。

## 模型

- **這一頁回答一個問題**：這個閘道對外承認哪些模型、每個模型是什麼類型、在哪幾條協定上
  真的可用、以及該打哪條端點。
- **三種類型**：對話、圖片、影片。對話模型掛在四條對話協定上；圖片與影片模型的協定那一列
  是空的——它們不屬於任何一條對話協定，走的是各自的媒體端點。
- **協定可用性是一格一格的徽章**，不是一句「支援」或「不支援」：這一列按模型逐條填。
  ⚠️ **今天目錄裡沒有一個模型是「一條協定上可用、另一條上不可用」**：那個對話模型四條
  協定全可用，三個媒體模型這一列全是空的。可以依協定篩選；篩出來一個都沒有時，這一頁
  直接說「這條協定上沒有可用的模型」，不畫一張空表。
- **端點那一列給的是「客戶端該打哪條路徑」**，與 [API.md](API.md) 出自同一份真源，
  本文不抄第二份。
- **目錄讀不出來時這一頁顯示一根破折號**，同螢幕還有一條讀取失敗的橫幅和一顆重試按鈕。
  ⚠️ **「讀不出來」與「一個模型都沒有」是兩件事，而今天把這件事講明白的那句文案只活在
  破折號的懸停提示裡**（`title=`）：滑鼠停上去看得到，觸控螢幕上出不來。
- ⚠️ **有一處已知的對外分歧，如實登記**：Gemini 那條協定的模型列表介面對**全部**模型
  一律聲明支援 `generateContent`，**包括那個影片模型**；而影片真正的路徑是「建任務 +
  輪詢」兩段式。面板這一頁按真實可用性填，兩邊對不上時以這一頁為準。

## 除錯台

- **兩把鑰匙嚴格隔離，這是這一頁最要緊的一件事。** 面板口令走 `x-admin-key`，只打
  `/admin/api` 那棵樹；除錯台用的是**閘道口令**（`GATEWAY_TOKEN`），走各條協定慣用的
  驗證標頭打對外那棵樹。兩把鑰匙分開存在瀏覽器裡，**登出時一起清掉**——共用或
  投影的機器上，不清的那一把會原樣留給下一個人。
- **閘道口令要你手動貼一次，沒有「一鍵填入」**：面板讀不到它的明文（憑證只寫不讀），
  只能把設定頁裡存著的末 4 位與你貼的這一把比一比，然後告訴你「一致」「對不上」
  還是「讀不到，這次比不了」。
- **三種模式，各自能配的東西不一樣**：

| 模式 | 打的是哪條端點 | 這一檔能配什麼 |
|---|---|---|
| 對話 | 四條對話協定各自的對外路徑 | 挑協定、挑模型，可以開串流 |
| 圖片 | 圖片生成那一條端點 | 只挑模型；沒有協定選擇器，也沒有串流開關 |
| 影片 | 建任務與查結果兩條端點 | 只挑模型；建完任務自動輪詢結果 |

**協定選擇器與串流開關只在對話檔出現**，不是被藏起來了：媒體那兩條端點在協定目錄裡
不屬於任何一條對話協定，擺一排點不動的按鈕只會讓人以為圖片也能挑協定、也能串流。

- **串流這一檔不顯示 token 數**：面板在串流下不讀用量，寫一個 `0` 會是假的，所以那一格
  乾脆不給數字。
- **影片是兩段式的**：先建任務拿到任務識別碼，再拿這個識別碼輪詢結果。輪詢**每 5 秒一次，
  上限是 60 次 / 5 分鐘**，先到哪條算哪條——今天這兩條恰好等價（60 次 × 5 秒正好是
  5 分鐘）；頁面被藏起來過的話打點會暫停而牆鐘照走，那時先到的是時長那一條。
- ⚠️ **真實上游生成一條影片要多久，本倉從來沒有量過。** 這兩條上限是拿來封住
  「一個忘了關的分頁變成一台永動打點機」的，不是從真實生成時長推出來的，本文
  也不對它們與真實生成時長的關係下任何結論。到上限時面板會明說「輪詢已經到上限，
  先停下了」並把任務識別碼擺在那裡——任務本身可能還在跑，你可以稍後自己拿這個識別碼再查。
- **建任務的回應裡沒有能用的任務識別碼時，面板不替你猜**：它只把固定的那幾格當識別碼讀，
  都讀不到就不輪詢，並把回應原文原樣擺出來。
- **每一次按「發送」都是真的打上游**：那一次請求與任何一次轉發走同一條路，用掉的那把
  key 照樣記帳（見速查表下面那句）。影片檔一次是 1 次建任務，加上最多 60 次輪詢查詢。
- **螢幕上最多保留 20 輪對話**，更舊的會從這一頁移除，面板會告訴你移除了幾輪；也可以
  按「清空對話」自己清掉。清的只是螢幕上這一份，伺服端什麼都不動。

## 設定

設定頁今天有四張卡：

| 卡 | 它管什麼 | 要注意的 |
|---|---|---|
| 認證密鑰 | 只有閘道口令一格；管理口令在這張卡上是唯讀顯示，面板改不了自己的鑰匙 | 憑證只寫不讀：輸入框留空 = 這一格不改 |
| 上游與冷卻 | 上游位址、逾時，以及冷卻與剔除的那幾個旋鈕 | 其中兩格是建實例時讀一次的，見本節末尾 |
| 註冊機 | 補池的全部旋鈕，**各條郵箱通道自己的憑證**（兩張對稱子卡），外加一個「進階」摺疊區 | 摺疊區裡那一格改的是每一次自動註冊的去向 |
| 整合範例 | 照抄就能跑的呼叫範例 | 位址取自你現在打開面板用的那個網域，口令是佔位符 |

- **每一格都攤開一個四元組**：儲存裡是什麼、環境變數裡是什麼、現在生效的是哪一個、
  以及是誰把它鎖住的。優先權是**環境變數 > 儲存裡的值 > 內建預設**；被環境變數鎖住的
  格子在這一頁改了不會生效，面板會直接告訴你該去改部署那一側的哪個變數。
- **憑證只寫不讀**：面板拿不到明文，螢幕上只有「已設定 / 未設定」與末 4 位。留空 = 不改；
  真要刪掉得按「清空」，而那一步會先告訴你清完會發生什麼——回落到環境變數裡的值、
  下一次重啟起不來、還是現在不影響任何東西。
- **儲存之後面板不只回一句「已儲存」**：它回讀一遍生效值、把真的變了的那幾格標示出來，
  再按這次改的是哪種欄位分岔說傳播。改的是普通欄位時，螢幕上那句話**開頭逐字是
  「本實例已經生效」**，後半句才是「別的副本 / isolate 最長多久才看得到這次改動」——
  它說的是本實例已經生效，不是「哪裡都還沒生效」。那個上界由設定快取與 KV 邊緣快取
  兩層相加得到，兩個數都在 [DEPLOY.md](DEPLOY.md) 的環境變數表裡。
- ⚠️ **有兩個例外欄位**：池快照快取與寫消除間隔（`POOL_CACHE_TTL_MS` 與
  `POOL_TOUCH_INTERVAL_MS`）是**建實例時讀一次**的 ⇒ 儲存之後**連本實例都還沒生效**，
  要重啟容器或者等 isolate 被回收。這次改動**只**碰了這兩格時，上面那句「本實例已經生效
  + 上界」**整條不顯示**，換成的是一句「已經落盤，但本實例也還沒生效」；兩種欄位一起改
  的話，兩句話同時出現。
- **面板改不了自己的鑰匙**：`ADMIN_TOKEN` 只從環境變數讀。要輪換它，改部署那一側的
  環境變數再重啟。
- **儲存裡那份設定載入不起來時這一頁變成診斷檢視**：逐條列出缺的是什麼，而且**表單仍然
  可以編輯**——那是唯一的出路。

## 危險區

**這張卡今天還不存在。** 設定頁上今天只有上面那四張，危險區計劃另開一張。
本文在它真的上線之前不寫它會做什麼：描述一個還不存在的功能，比什麼都不寫更壞。
上面那張表的行數是從面板自己的卡數派生出來的，所以危險區一落地，這份文件就會被測試
逼著回來改。

## 面板不做什麼

- **不輪換自己的鑰匙**：`ADMIN_TOKEN` 只從環境變數讀，面板既改不了它，也沒有
  「讓已經發出去的工作階段立刻作廢」這種撤銷路徑。換鑰匙 = 改部署那一側的變數，
  再重新部署或重建容器。
- **不回顯任何憑證的明文**：後端對憑證只回「配沒配」加末 4 位，所以面板做不出
  「把我的口令填進來」這種按鈕——那需要在後端開一個明文回顯的口子，而那個口子一開，
  「憑證只寫不讀」整條就沒了。
- **不代替 `wrangler secret` 與 `.env`**：這一頁改的是儲存裡那一份設定，而環境變數的
  優先權更高。兩邊不一致時螢幕上會有鎖定標記，但把環境變數本身改掉這件事只能在
  部署那一側做。
- **不替你把遠端媒體拉下來**：除錯台裡的結果位址是原樣列出來的，隨時可以複製；
  **只有 `http` / `https` 開頭的那種才多給一顆「開啟」連結**——`javascript:` / `blob:` /
  `file:` 這些即便上游真的返回了也不給，點開會得到一個由上游內容決定的頂層文件；
  只有 `data:` 形式的圖片才會內嵌顯示，那一檔不向任何第三方發請求。

## 排障

- **打不開，而且是 `404`**：這個部署沒設 `ADMIN_TOKEN`，或者設了但不合規。整棵樹
  沒註冊，所以外面也看不出這裡有沒有後台。
- **打不開，而且是 `401`**：口令本身不對，多半是它已經被輪換過了。⚠️ **別把這一檔與
  「面板把你退回登入框」混為一談**：12 小時那條視窗是面板自己判的，到點時它一個請求都
  不會發出去，伺服端那邊什麼紀錄都不會有。兩種都只要重新輸入一次。
- **打不開，而且是 `503`**：`ADMIN_TOKEN` 與儲存裡的閘道口令撞成了同一個值。這條規則
  在每一個管理請求上複查，事件板塊與日誌裡會有一條 `admin.token_conflict`。
  ⚠️ **把儲存裡的閘道口令改回去只恢復可用性**：那把管理口令必須按已外洩處置，
  完整步驟在 [DEPLOY.md](DEPLOY.md) 裡，兩步都做完才算處置完。
- **口令貼進去，登入框當場說「這個口令裡有不被接受的字元」**：面板在發請求之前先判字元
  集，只收可列印 ASCII（`0x20–0x7E`）。碼點超過 `U+00FF` 的漢字、emoji、零寬空格，以及
  NUL / LF / CR，瀏覽器根本發不出去；`é` / `£` 這類其實發得出去，但本閘道基於跨執行時
  編碼的考量同樣不收。這一檔**一個請求都不會發出去**，所以伺服端連一條登入失敗都沒有。
  ⚠️ **部署那一側真配了這樣的口令時你看不到這句話**：那時整棵樹壓根沒註冊，你拿到的是
  上面那條 `404`。
- **螢幕上是舊值**：設定與池快照各有各的快取視窗，外面還疊著一層 KV 邊緣快取。兩條的
  上界與代價都在 [DEPLOY.md](DEPLOY.md) 的環境變數表裡，本文不抄第二份；概覽頁那兩條
  「幾秒前讀到的」就是給這件事看的。
- **報錯是後端原話，不是你的語言**：面板對**它認得的**錯誤碼顯示本語言文案；碰上它
  不認得的碼，就把後端那句原話擺出來，並在旁邊標一句「這句是後端原話，本面板還沒有
  這條錯誤碼的譯文」。⚠️ **別讀成「所有錯誤都會用你的語言顯示」**——認不出來的那些
  不會，而面板寧可把這件事標出來，也不冒充成一句譯文。
