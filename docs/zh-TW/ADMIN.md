# 管理面板

**語言：** [English](../en/ADMIN.md) | [简体中文](../zh-CN/ADMIN.md) | 繁體中文 | [日本語](../ja/ADMIN.md) | [한국어](../ko/ADMIN.md)

管理面板是**可選的**：沒設 `ADMIN_TOKEN` 時整棵 `/admin` 樹根本不註冊，而閘道照常轉發。
本文講的是面板上看得見的那一半——每個板塊回答什麼問題、螢幕上那些數字是什麼口徑、
哪些動作會寫入儲存。**變數本身（預設值、取值範圍、代價）全倉只有一份，在
[DEPLOY.md](DEPLOY.md) 的環境變數表裡**，本文一律只給指路，不抄第二份。

本文涵蓋：怎麼進面板，以及概覽、Key 池、註冊機、事件、用量這幾個板塊。

## 怎麼進面板

- **位址**：`https://<your-gateway>/admin`，把 `<your-gateway>` 換成你自己的閘道位址。
  帶尾斜線的 `/admin/` 會自動跳到 `/admin`，兩種手動輸入的寫法都進得去。
- **前置條件只有一條**：部署時設好 `ADMIN_TOKEN`。它必須至少 24 位、只由可列印 ASCII
  組成、並且與 `GATEWAY_TOKEN` 不同。這三條各自的理由、邊界，以及不合規時會記下哪條
  事件，都在 [DEPLOY.md](DEPLOY.md) 的「管理面板相關變數」一節。
- **沒設或不合規時，`/admin` 給的是 `404` 而不是 `401`**：整棵樹壓根沒註冊，所以它
  不會順帶告訴外面「這裡有個後台」。面板打不開也**不影響閘道轉發**。
- **口令原樣存在瀏覽器的 localStorage 裡**，面板會在 12 小時後要求你重新輸入。
- 那個上限只縮短這份 localStorage 值的可用視窗，**不等於撤銷**：撤銷的唯一路徑是換掉
  `ADMIN_TOKEN` 再重新部署 / 重建容器。請把面板放在 TLS 之後，並且只在你信任的機器上
  打開它——完整論證見 [DEPLOY.md](DEPLOY.md) 的「管理口令洩漏」那一段。

## 八個板塊速查

| 板塊 | 它回答什麼問題 | 唯讀還是會寫 | 依賴哪個開關 |
|---|---|---|---|
| 概覽 | 這個部署現在是什麼形態，池子還剩多少可用 key | 唯讀 | – |
| Key 池 | 每一把 key 現在是什麼狀態，為什麼不可用 | 會寫 | – |
| 註冊機 | 自動補池在不在跑，上幾輪補了什麼 | 會寫 | `REGISTRAR_ENABLED` |
| 事件 | 最近發生過哪些維運級別的事 | 唯讀 | – |
| 用量 | 請求量、成功率、延遲隨時間怎麼變 | 唯讀 | `USAGE_STATS_ENABLED`（只管第二層） |
| 模型 | 閘道對外承認哪些模型，各自支援什麼模態與協定 | 唯讀 | – |
| 除錯台 | 用一次真的請求驗一遍某條協定通不通 | 打上游 | – |
| 設定 | 執行期設定現在是什麼值，哪幾項被環境變數鎖住了 | 會寫 | – |

「會寫」指的是**寫儲存**；「打上游」指的是不寫儲存、但會真的向上游發一次請求。

## 概覽

概覽回答一個問題：**這個部署現在是什麼形態、池子還剩多少可用 key。**

- **池子五個桶**：總數 / 可用 / 冷卻中 / 已剔除 / 已停用。五格恆顯示，一個真實的 `0`
  本來就是真話；**讀不出來時那一格顯示 `—`，絕不偽造 `0`**——這兩件事在螢幕上必須
  長得不一樣。
- **執行期與儲存自述**：執行期名字、版本、伺服端時間、儲存後端、可寫與否，以及
  Node 形態才有的記憶體 / 存活時長 / PID。這些一律取自介面回傳的資料，面板不去嗅探
  自己跑在哪種執行期上；Worker 形態沒有常駐行程，那三格寫的是「無常駐行程」，
  不是 `0`、也不是空白。
- **兩條新鮮度**：池快照與設定各有各的「幾秒前讀到的」。它們不是同一條時間線，所以
  分開顯示。池快照那條的遲滯由 `POOL_CACHE_TTL_MS` 決定，還要再疊一層邊緣快取，
  上界與代價在 [DEPLOY.md](DEPLOY.md) 的那一格裡寫著。
- **第一層累計用量**：請求數 / 成功 / 失敗 / 客戶端錯誤 / 成功率。它是整池所有 key 的
  累計聚合，因此標著 `≈`：單把 key 的計數在並行下會少計（KV 沒有 CAS），而且最多晚
  一個 `POOL_TOUCH_INTERVAL_MS` 才寫入。
- **設定摘要**：註冊機開關、主備通道、`TARGET_KEYS` 這幾項的目前生效值。被環境變數
  鎖住的欄位帶一個鎖定標記——那幾項在設定頁改了也不會生效，因為環境變數的優先權更高。

## Key 池

- **桶徽章是一次優先權投影**，不是四個獨立標誌：一把 key 同時滿足多個條件時，按
  已停用 > 已剔除 > 冷卻中 > 可用 取第一個。所以一把「被停用、同時還在冷卻」的 key，
  徽章上寫的是「已停用」——它的冷卻並沒有消失，只是徽章上看不見。
- **八個單條動作**：停用、啟用、清冷卻、清失敗計數、取消剔除、改備註、驗活、刪除。
- **三個批次動作**：批次停用、批次清冷卻、批次刪除。
- **一次最多匯入 200 把 key**。超過這個數直接 `400`，**不靜默截斷**——截斷意味著你以為
  匯進去了而其實沒有。
- **「重設已存在 key 的狀態」這個勾選框到底重設什麼**：它重設的是**系統判定的失敗態**
  ——失敗計數、冷卻截止時刻、冷卻原因、剔除標記、剔除原因。它**刻意不動**另外四樣：
  停用狀態（那是你自己按下的開關，一次貼上不該把它靜默翻回去）、加入時間（來歷不是
  失敗態）、用量統計（歷史不是失敗態）、備註（你寫給自己看的話）。
- **刪除必須先停用**：直接刪一把還在用的 key 會被拒絕。這條約束在批次路徑上不是整批
  失敗，而是逐項給出原因。
- **單把驗活**會拿這把 key 真的打一次上游。清單裡的「最後使用」與用量計數是攢著寫入的，
  精度最粗到 `POOL_TOUCH_INTERVAL_MS` 這個間隔。

## 註冊機

面板上的註冊機板塊是**索引，不是說明書**：補池的全部規則、通道怎麼選、要自備哪些憑證、
出事怎麼排查，全在 [REGISTRAR.md](REGISTRAR.md) 裡，本文不抄第二份。板塊上看得到的是：

- **兩條郵箱通道是平級的**，沒有預設值：主通道必須明確指定，備通道可以不配。板塊顯示
  它們各自的角色（主 / 備）與憑證配沒配。
- **補池歷史**：每一輪什麼時候跑的、走的哪條通道、由定時器還是由人觸發、跑了多久。
- **通道測試只讀取這條通道的可用網域清單**，不建郵箱、不註冊帳號、不消耗任何名額。
- **「立即補池」有四條護欄**，任何一條不滿足都不會啟動：同副本的在途守衛、跨副本的
  儲存短鎖、兩次手動補池之間的最小間隔、每天的手動次數上限。四條各自的錯誤碼、算式
  與殘餘風險在 [REGISTRAR.md](REGISTRAR.md) 的「面板的「立即補池」」一節。
- 註冊機沒打開（`REGISTRAR_ENABLED` 不為 `true`）時板塊照樣看得見，只是狀態顯示為關閉，
  「立即補池」會被後端拒絕。

## 事件

- 這裡只有**低頻結構化事件**：設定讀取失敗、池索引重建、管理介面登入失敗這類維運診斷，
  加上註冊機的補池事件與面板自己的寫操作。**key 被轉發路徑自動打進冷卻或剔除時目前
  不產出事件**——那一段要回 Key 池板塊看那把 key 自己的狀態。
- **工具列**：按級別篩選、按文字搜尋、暫停自動重新整理、清空、下載。「清空」只清螢幕上
  這一份清單，**不動伺服端已經寫入的事件**；要重看請點「下載」或重新整理頁面。
- **事件按小時分視窗存放，一共留 24 個視窗**——也就是整整一天，更早的會自然過期，
  面板上再也查不到。
- 四種警告條各自在說一件不同的事：

| 警告條 | 它在說什麼 | 你該做什麼 |
|---|---|---|
| 丟棄 | 本副本的事件緩衝把最舊的幾條擠掉了，它們沒來得及寫入 | 事件產生得比寫入快；去容器日誌 / Workers Logs 裡找那一段 |
| 預算 | 本副本今天的事件寫入預算已經用完 | 同上：沒寫入的那些仍然在日誌裡 |
| 截斷 | 這一頁沒顯示全部符合條件的事件 | 收窄篩選條件，或者縮短要看的時間範圍 |
| 游標 | 擷取位置不合契約，或者領先於伺服端時鐘 | 面板已自動重拉；反覆出現說明事件儲存被本閘道之外的東西寫過 |

## 用量

- **用量分兩層，第一層永遠在**。第一層是整池累計的那幾個數（概覽頁頂上那張卡用的就是
  它），不需要任何開關。第二層是按天 / 小時 / 模型 / 協定分解的時間序列，由
  `USAGE_STATS_ENABLED` 控制，**預設是關的**。
- **關著的時候這一頁不畫空圖表**：一張全是 `0` 的圖會被讀成「這段時間沒人用」，而真相
  是「這個部署根本沒在記帳」。這兩件事不許長得一樣。
- **四檔時間範圍**：`24h`、`3d`、`7d`、`30d`。
- **最多保留 30 天**，更早的資料已經過期。最長那一檔一次要把整段區間的分片全部讀回來，
  它在 Cloudflare Worker 上是否總能跑完，本倉尚未在真機上量過——失敗時這一頁如實顯示
  為讀取失敗，不會給出一份看起來完整的數字。
- **這裡的數字標著 `≈`，三個來源各不相同**：① 未寫入的尾巴——計數先攢在實例記憶體裡，
  隔一陣才批次寫入，這段視窗有多長面板自己會告訴你；② 短命實例——那一段還沒寫入就被
  回收的話就沒了；③ 同一天裡的分片只有 2 個槽位，同時寫的副本比這更多時，同槽位是
  後寫覆蓋前寫。
- **讀不出來時顯示 `—`，不是 `0`**：「今天真的是 0 次請求」「第二層沒開」「這一次讀失敗了」
  是三件事，面板不許把它們畫成同一個樣子。
